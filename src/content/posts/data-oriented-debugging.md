# Abstract

Programmers routinely instrument and run their code with tools such as print statements or
breakpoints in order to understand how their programs behave at runtime. When multiple tools are
available to programmers, how should we think about their strengths and weaknesses? In this paper,
we provide one lens for comparison called data-oriented debugging. In this lens, a programmer has
data needs and expresses them as queries to their debugging tools. Queries reach into clusters of
program data organized by place and time. Tools differ in which of these queries they make easy. We
develop this lens through formative interviews with professional programmers, a comparative tool-use
study, and an analysis of existing debugging tools. We offer the lens as a reflective aid for tool
designers and researchers to assess the capabilities of a debugging tool of interest.
